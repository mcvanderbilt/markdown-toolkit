## 1. What this package is

An installable R package (`devtools` + `roxygen2` + `testthat`) of functions
for working with Markdown files: parsing/extraction, validation/linting,
conversion/rendering, and generation/templating (including building a
Markdown table from a data file such as CSV or Excel). Matthew writes or
adapts core function logic; Claude drafts, documents, tests, and maintains
package structure. Full division of labor and conventions:
`claude/custom-instructions.md` (backup of the claude.ai Project's custom
instructions; also present in the Project's own knowledge base).

## 4. Standing workflows

**Adding a new function**
1. Confirm scope and check whether a suitable CRAN dependency already
   covers part of the problem (minimize new dependencies — see §5).
2. Write the function in `R/`, `snake_case`, tidyverse style.
3. Add a full `roxygen2` block (`@param`, `@return`, `@examples`, `@export`).
4. Add a `testthat` test covering the happy path and at least one
   failure/edge case.
5. Run `devtools::document()` and `devtools::check()`.
6. Add a `NEWS.md` entry.

**Adding a new CRAN dependency**
Propose it (what it solves, why base R/existing deps aren't enough), get
Matthew's sign-off, then add it to `DESCRIPTION` `Imports`/`Suggests` with a
minimum version if relevant.

**Deferring something**
Add it to `TODO.md` under the right section rather than leaving it only in
chat. Once there's real activity beyond solo development (collaborators,
external users), move to GitHub Issues instead of hand-maintaining this
file — that's the more typical home for an R package's backlog.

**Making a breaking change**
Bump the package's MAJOR version, document the change in `NEWS.md`, and
confirm with Matthew before merging, per `claude/custom-instructions.md`.

## 7. Package naming note

R package names may only contain letters and numbers and must start with a
letter — no hyphens, underscores, or other punctuation. Since the repo is
named `markdown-toolkit`, `DESCRIPTION`'s `Package:` field uses `mdtoolkit`
instead. `library(mdtoolkit)` loads it; the GitHub repo name is unaffected.
Open question in `TODO.md` if you'd rather use a different package name
(e.g. `mdtools`, `mdkit`).
